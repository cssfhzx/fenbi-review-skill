# 粉笔练习 PDF 复盘

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Python 3.9+](https://img.shields.io/badge/python-3.9%2B-blue.svg)](https://www.python.org/downloads/)

把粉笔 App 导出的练习 PDF 变成一份可执行的复盘文档：**解析文本层 → 判定对错 → 错因分析 → 生成 docx → 归档错题本**。

粉笔导出的 PDF 带完整文本层（题干、选项、`正确答案：X`、`你的答案：X`），所以不需要 OCR、不需要看图判读手写答案。一条命令拿到结构化数据：

```
解析完成: 快速智能练习.pdf
共 6 页 / 15 题，答对 11，答错 4，正确率 73.3%
  Q3   [类比推理  ] ×  我=D 正=B  白兰地：烟酒
  Q7   [资料分析  ] ×  我=B 正=C  2016~2022年期间，G省博物馆数量年均增加
```

剩下的工作是**错因分析**——那是模型该干的活，也是这个 skill 真正的重心。

## 安装

```bash
pip install pymupdf python-docx
git clone https://github.com/cssfhzx/fenbi-review-skill.git
```

作为 DSH / Claude Code 等 agent 的 skill 使用时，把仓库放到 skill 扫描目录（DSH 默认 `~/.agents/skills/`），`SKILL.md` 的 frontmatter 会被自动识别。

## 快速开始

```bash
# 1. 解析 PDF → <name>_parsed.json + <name>_imgs/
python scripts/fb_parse.py "D:/Download/快速智能练习.pdf"

# 2. 写错因分析，存成 analyses.json（格式见下）

# 3. 生成复盘 docx
python scripts/fb_pipeline.py "D:/Download/快速智能练习.pdf" \
  --analyses analyses.json \
  --title "快速智能练习 · 复盘" \
  --out "复盘.docx"

# 4. 可选：归档到错题本
node scripts/fb_archive.js "D:/Download/快速智能练习_parsed.json"
```

没有 `analyses.json` 也能跑，docx 会生成带占位符的骨架，用于先看结构再补内容。

## 输出文档结构

| 章节 | 内容 |
|---|---|
| 一、基本情况 | 来源、题量、正确率、模块分布、错题分布 |
| 二、错因分布 | 表格：错因类型 / 题号 / 说明 |
| 三、逐题复盘 | 每题一表（题干+选项 / 我的答案 / 正确答案 / 错因）+ 解析 + 搭配库 |
| 四、做对但值得记录的题 | 有 `note` 的正确题 |
| 五、训练计划 | 编号列表 |

## 错因分析格式

`analyses.json` 是一个以题号为键的对象：

```json
{
  "5": {
    "tag": "选项功能误判",
    "cause": "② 不明白选项的功能",
    "note": "「高高在上」只用于人，不能修饰法律",
    "analysis": [
      "「高高在上」形容人脱离实际、脱离群众，主语必须是人，不能修饰「法律」。",
      "题干锚点是「一辈子不打交道」——强调距离远，对应「遥不可及」。",
      "「红线」是禁止性边界，对应「警戒」而非「教育」。"
    ],
    "colloc": [
      "高高在上　→　只用于人（不修饰制度、法律、条文）",
      "遥不可及　→　距离远、够不着",
      "警戒　→　红线、边界"
    ]
  },
  "_plan": [
    "成语适用对象清单每日过一遍，见词先问「主语是谁」。",
    "多空题铁律：任一空站不住即排除整项。"
  ]
}
```

| 字段 | 用途 |
|---|---|
| `tag` | 题目标签，显示在标题旁 |
| `cause` | 错因归类，进「二、错因分布」表 |
| `note` | 一句话说明，进分布表「说明」列；也用于正确题 |
| `analysis` | 解析正文，逐条 bullet |
| `colloc` | 搭配库，蓝色缩进行 |
| `_plan` | 训练计划（全局） |

完整示例见 [`samples/`](samples/)：`analyses-example.json`（资料分析 + 类比推理）、`analyses-yanyu.json`（言语理解 20 题）。

## 写法约定

这四条决定了复盘文档有没有用，细节见 [`references/analysis-writing.md`](references/analysis-writing.md)。

**锚点优先。** 每道错题的解析必须指出题干里的锚——分号对举、顿号并列、转折词、定义句、后文评价句、惯用搭配——而不是凭语感解释。

**colloc 记「词 + 对象」，不记释义。**

```
✅ 经久不息　→　只配掌声、欢呼（不配方式、风尚）
❌ 经久不息　→　形容持续很长时间
```

**错因归类要能对应一个改法。** 用 [`references/cause-taxonomy.md`](references/cause-taxonomy.md) 的编号格式，覆盖言语/判断/资料/数量/常识五大模块。不写「理解错误」「粗心」「基础不牢」这类无法落地的归类。

**训练计划要有数量、时间、验收标准。** 不写「加强积累」，写「每天过一遍词+对象清单 9 条，见词先问主语是谁」。

## 题型识别

解析器按优先级匹配，命中即停：

| 优先级 | 题型 | 判据 |
|---|---|---|
| 1 | 图形推理 | 短题干 + 选项为空（纯图） |
| 2 | 语句排序 | 含 ①②③ 序号 + 「排列/语序/顺序」 |
| 3 | 逻辑填空 | 「依次填入」+ 横线 |
| 4 | 语句填空 | 「填入」+ 横线（单空） |
| 5 | 标题填入 | 「最适合做这段文字标题」 |
| 6 | 资料分析 | 根据资料/表1/同比/占比/百分点/年均/约占 等强信号 |
| 7-9 | 片段阅读 | tail 含「意在/主要/符合」等，分意图/中心/细节 |
| 10 | 语句表达-下文推断 | tail 含「接下来/下文」 |
| 11 | 逻辑判断 | 含「如果/只有/除非/加强/削弱/前提」 |
| 12 | 类比推理 | 题干极短 + 含冒号 |
| 13 | 数学运算 | 含数字 + 计算类词 |

**资料分析必须排在片段阅读前面**——它的材料段很长，容易被误判成片段阅读。只看 `stem[-60:]`（问法在末尾）能大幅降低误判。

## 已知限制

- 只处理粉笔导出的**带文本层** PDF。扫描件、拍照版不支持。
- 资料分析题的图表解析器读不出数值，需要打开 `_imgs/` 看图。
- 题型识别是启发式规则，智能组卷题型随机时可能判错，生成后看一眼「模块分布」，不对就改 `guess_type()`。
- 图形推理题的选项是图片，解析器只能标出题型，无法判对错逻辑。
- 归档功能（`fb_archive.js`）写入 `~/.kaogong-study-tracker/`，配套 [kaogong-study-tracker](https://github.com/) 使用；不需要归档可跳过这步。
